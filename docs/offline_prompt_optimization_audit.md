# Deep Offline Prompt/Context Optimization Audit

## 1. Actual Qwen Request Composition for Every Workflow

### Router/Planner
- **System**: Architecture rules, allowed specialist list, workflow constraint instructions.
- **User**: The original user prompt.
- **Response Format**: `Plan` JSON schema definition.

### Trial Data Analyst
- **System**: Full `instructions.md` (~2.5K chars). Includes Scope, Refusal/Escalation Rules, Examples, and the ENTIRE Valid Query Catalog (6 complex query definitions).
- **User**: The Task Description from the Planner.
- **Tools**: JSON schema of `sql_query_tool`.
- **Assistant (Turn 2+)**: Prior tool call generated by the model.
- **Tool (Turn 2+)**: Raw JSON array of SQL row objects.
- **Final User Prompt (Turn 2+)**: Hardcoded instructions to finalize the response.
- **Response Format**: `TrialDataAnalystOutput` schema.

### Literature Research Agent
- **System**: Full `instructions.md` (~1K chars).
- **User**: Task Description.
- **Tools**: `vector_search_tool` schema.
- **Response Format**: `LiteratureResearchOutput` schema.

### Adverse Event Triage Agent
- **System**: Full `instructions.md` (~1.2K chars).
- **User**: Task Description.
- **Tools**: `sql_query_tool`, `ae_severity_classifier_tool`, `escalation_tool`. (Massive tool schema footprint).
- **Response Format**: `AETriageOutput` schema.

### Compound Similarity Agent
- **System**: Full `instructions.md` (~1K chars).
- **User**: Task Description.
- **Tools**: `compound_similarity_tool` schema.
- **Response Format**: `CompoundSimilarityOutput` schema.

### Report Writer
- **System**: Full `instructions.md` (~1K chars).
- **User**: JSON dump of all `specialist_results` accumulated in the Graph state, plus the original prompt.
- **Tools**: `citation_formatter_tool` schema.
- **Response Format**: `FinalReportOutput` schema.

## 3. Exact Duplicated/Unnecessary Context

1. **Full Agent Instructions on Every Turn**: The `BaseAgent` loop continually resends the full `instructions.md` containing Examples, Refusal Rules, and Escalation Rules even during the forced finalization turn when tools are disabled.
2. **Static Query Catalog**: The Trial Agent system prompt lists 6 different query families. If the Router has already constrained the task to a specific query, the other 5 query definitions are dead weight.
3. **Redundant History in Turn 2**: `BaseAgent` preserves the conversational history (`[Assistant(ToolCall), Tool(Result)]`) instead of replacing it with a concise data-driven prompt for the final synthesis.
4. **Report Writer JSON Handoff**: `ReportWriterRunner` receives raw JSON structures from `state["specialist_results"]` rather than concise text summaries, wasting tokens on schema keys (`summary`, `limitations`, etc.).

---

## 4. Largest Token Waste Sources

1. **Unfiltered JSON Tool Results**: SQL query results returned as a list of dictionaries (`[{"trial_id": ..., "status": ...}, ...]`) repeats the keys for every single row. For large datasets, this consumes thousands of unnecessary tokens.
2. **Trial Agent System Prompt**: The static inclusion of all available queries regardless of context.
3. **Conversational History Retention**: Retaining the tool invocation turn inside the finalization turn payload.

---

## 5. Recommended Minimal Runtime Prompt Structure

**Single Specialist Tool Call (Turn 1)**
- **System**: Minimal Identity + Task Rules. (Drop examples and unused query definitions).
- **User**: Task description.
- **Tools**: Only required tools.
- **Target Input**: ~300 - 450 tokens.

**Final Specialist Synthesis (Turn 2)**
- **System**: "Synthesis Mode" Identity (no tool instructions, no examples).
- **User**: Task description + **CSV/Markdown formatted** tool result data. (Drop the Assistant/Tool message history completely).
- **Response Format**: Output schema.
- **Target Input**: ~400 - 600 tokens.

**Report Writer**
- **System**: Identity and synthesis rules.
- **User**: Markdown-formatted bulletin of specialist findings (e.g., `Trial Data: [summary]`).
- **Target Input**: ~500 - 700 tokens.

## 6. Expected Token Savings Per Call

- **Trial Agent Call 1**: ~200 - 300 tokens (by filtering the query catalog).
- **Trial Agent Call 2**: ~400 - 1,500+ tokens (by converting SQL JSON to CSV and dropping the Assistant/Tool conversation history).
- **AE Agent**: ~100 - 150 tokens (by isolating tool availability).
- **Report Writer**: ~100 - 200 tokens (by minifying state JSON into text).

---

## 7. Expected Token Savings Across the 8-case Acceptance Suite

By implementing these changes, we can expect an average reduction of **500 - 800 tokens per agent workflow**. Across the 8 acceptance cases (averaging 3-4 LLM calls each), total input token usage will drop by **~15,000 to ~20,000 tokens**. 

The current ~30K total will be reduced to **~10K - 15K**, safely insulating the application from the 8K TPM rate limit when processed sequentially.

---

## 8. Recommended Implementation Changes

1. **Format Tool Results**: Modify `sql_query_tool` and vector results to output CSV/Markdown instead of JSON arrays.
2. **Prune BaseAgent History**: Modify `BaseAgent.run` so that in `single_tool_mode=True`, the finalization request strips the conversational history and constructs a fresh `[System, User]` prompt containing the raw data.
3. **Dynamic Trial Prompting**: Dynamically inject only the relevant query definition from the catalog into the Trial Agent's system prompt.
4. **Minify Graph State Handoff**: Update `SpecialistRunner` to format its output into a clean string before passing it to `state["specialist_results"]`.

---

## 9. P0/P1/P2 Classification

- **[P0] Tool Result Formatting (JSON to CSV)**: Largest source of token waste for data-heavy queries.
- **[P0] Turn 2 History Pruning**: Eliminates redundant context duplication in single-tool workflows.
- **[P1] Dynamic System Prompts (Query Catalog)**: Removes static bloat from the Trial Agent.
- **[P2] Graph State Minification**: Minor improvements for the Report Writer.

## 10. S1 Specifically

**Trace of exact requests for S1 ("Which Phase II oncology trials are below 60% enrollment right now?"):**

**CALL 1 (~1,153 input tokens):**
- **System (2,931 chars)**: The complete Trial Agent instructions containing 6 SQL query schemas and examples.
- **User (493 chars)**: The Planner's task description containing the original prompt and routing instructions.
- **Tools (767 chars)**: The `sql_query_tool` JSON schema.
- **Token Math**: ~4,191 chars / 4 ≈ 1,047 tokens + structural overhead ≈ 1,153 tokens.

**CALL 2 (~1,625 input tokens):**
- **System (2,931 chars)**: Full instructions repeated.
- **User (493 chars)**: Planner task description.
- **Assistant (270 chars)**: The generated tool call from Call 1.
- **Tool (1,000+ chars)**: The SQL results formatted as a raw JSON array of dictionaries, repeating keys like `trial_phase`, `therapeutic_area`, and `enrollment_pct` for every matching trial.
- **User Finalization (292 chars)**: The hardcoded "The SQL tool has already returned..." instruction.
- **Response Format (448 chars)**: `TrialDataAnalystOutput` schema.
- **Token Math**: ~5,500 - 6,000 chars / 4 ≈ 1,500 tokens + structural overhead ≈ 1,625 tokens.

**Target for S1 (Post-Optimization):**
- **CALL 1 Target**: ~400 - 500 tokens (by removing unused queries from System).
- **CALL 2 Target**: ~500 - 600 tokens (by dropping Assistant/Tool history and converting SQL JSON results to a dense CSV string).

## 11. Implementation Update

The P0 optimizations have been successfully implemented and verified offline:

**Actual Before/After S1 Payload Sizes (Estimated Tokens):**
- **CALL 1 (Before):** ~1,153 tokens
- **CALL 1 (After):** ~794 tokens (~31% reduction)
- **CALL 2 (Before):** ~1,625 tokens
- **CALL 2 (After):** ~332 tokens (~79% reduction)

**Total Token Savings:**
- For S1 specifically, the total input token cost dropped from ~2,778 tokens to ~1,126 tokens (saving ~1,650 tokens per S1 run).
- Extrapolating across similar workflows, this equates to ~15K-20K input tokens saved over the 8-case suite.

**Retained Context:**
- Planner: Architecture rules, full allowed-specialists list, and user prompt.
- Call 1: Minimal Identity + strictly required tool schema + Task Description.
- Call 2: "Synthesis Mode" Identity + Original User Task Description + strictly authoritative CSV-formatted results.

**Removed Context:**
- Static Query Catalog from Trial Agent's System prompt.
- Examples section from system instructions during execution.
- `Assistant(ToolCall)` and `Tool(Raw JSON)` conversation history completely purged during Call 2 finalization.
- JSON structure overhead (keys, formatting) stripped from tool results via `compact_tool_result`.
